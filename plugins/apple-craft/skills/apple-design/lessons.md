# Lessons from real work

What got approved and what got rejected across many rounds of building apps, websites, icons and a launch video for a demanding designer. Each line is a real reaction, not a theory. Read it before starting, and again before showing anything.

## The big ones

- **Real beats drawn, every time.** A real screenshot, recording or system asset always wins over a copy rebuilt from shapes, however carefully made. "Use real panels", "use a real image", "use the icon from the website". If something isn't built yet, build it for real and capture it.
- **Clean and correct is not enough.** Pages that passed every rule were still called forgettable. Every product page needs one moment that belongs to it alone.
- **Never copy a signature.** A second site that reused the first site's effect got "it looks like that other site, just redesigned". The shared craft (space, type, real pictures, buttons) can repeat; the signature can't.
- **Small numbers matter.** A button moving 1 px on hover, a 4 px gap that differs between two screenshots, padding that's 8 px tighter on one side. All of these were noticed and rejected. Measure; don't eyeball.
- **When asked to fix one thing, fix only that thing.** "Just do this one thing" means one change. Unrequested changes to size, speed or spacing got "revert it, ours was better".
- **Keep a backup before a big restyle.** Big changes sometimes lose what made the old version good ("we just lost so much of our Apple style"). Be able to go back in one step.

## Websites

| Rejected | What worked |
|---|---|
| Buttons that lift a pixel on hover | Colour, glow or a label-to-icon morph; the button never moves |
| A Download button at lower opacity than the others | Every button at full strength; hierarchy comes from fill, not transparency |
| Emoji as icons | SF Symbols, or nothing |
| A system fallback font, or a font that "looks off" | SF Pro (the system font stack) with Apple's tracking |
| Tight side padding on wide screens | Generous, equal side margins; the content column never touches the edges |
| Window screenshots with black or grey corners | Crop to where the window is fully opaque, keep the real rounded corners |
| A product window floating in space | The window sitting just above a Dock on a real Mac scene |
| A window placed too far above the Dock | The same small gap as the others, measured in pixels |
| Animations sped up "to feel snappier" | The original, calmer timing |
| A broken hover animation on one button | Every button with the same, working morph |
| A tall empty column next to a long list | A sticky heading, or the heading stacked above the list |
| A FAQ that snaps open with no motion | Height animation, fading answer, rotating chevron |
| A square focus ring cutting through divider lines | A rounded ring that matches the control and stays inside it |
| "Download" for a product that isn't out | A button that says what it does: "Notify me at launch" |
| Notes left on the page ("icon is temporary", "concept") | Nothing that only makes sense to the builder |
| A loud, saturated wallpaper behind the product | A calm wallpaper so the product reads |
| A teal toggle and other system controls in a brand colour | System controls keep the system colours from Apple's kit |
| A mock-up window that's a box with a line of text | A window built from real macOS parts: toolbar, sidebar, rows, symbols |

## Pictures and icons

| Rejected | What worked |
|---|---|
| An icon scaled up from a small file ("extremely blurry on the sides") | The largest source, usually the 1024 to 2048 px asset |
| A cut-out with a dark outline around it | The outline traced from the shape's own rim, checked at 300 % |
| A redesign that kept "the same thing" after being called bad | A real change of approach, compared side by side with the original |
| "Spot the differences" ignored | Put the new and original next to each other at the same size and list every difference |
| A picture reused from an older release | A new picture of this release's change |
| Test data in a picture ("Version 0.1.0") | Real, current data |

## Motion and video

| Rejected | What worked |
|---|---|
| UI rebuilt from shapes for a video ("looks like slop") | The real UI, recorded |
| A magnified copy of the UI over the real one | A camera move on the real recording |
| The last frame of a clip frozen on screen after it ended | A check frame just after every clip's end |
| A made-up 3D character to represent the product | Only things the product actually shows |
| Hard cuts and dips to black between every scene | Scenes that push and blur into each other |
| Fast, tiny action in a wide shot | Staged footage: the UI big, centred and slow, recorded for the camera |
| Generated music | A real track; it lifts a video more than any edit |
| "Look at the dot" when the feature is "follow the light" | Show exactly what the feature does, in motion |

Footage limits a video more than editing does. If a scene isn't working after two edits, re-record it.

## Copy

- Short and plain: "Your Mac. Unlocked." beats a sentence of features.
- One headline, one supporting line, one action. Nothing repeated.
- Never promise something the product can't do yet; say what's true ("Tide isn't out yet").

## Process

- **Ratings from the builder are always too high.** Every self-score of 8 turned out lower once the person saw it. Report what's missing, not how good it is.
- **Look at the real thing, not a report.** Reload, screenshot, zoom. Several "done" claims were wrong because only the code was read.
- **Show the person early.** The fastest progress came from a screenshot shown halfway, not a finished page shown once.
- **Ask what they're picturing** when the request is vague ("make it peak"), then offer three concrete options with a pick.
- **When something keeps failing, change the approach, not the parameters.** Five tweaks to a drawn panel never beat switching to the real recording.
